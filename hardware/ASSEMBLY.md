# 装配与校准

本文集中说明硬件准备、鸭形装配和本仓库 `otto-duck` 固件的校准。硬件复用现成套件，外壳使用社区模型。

`otto-duck` 基于小智固件中的 Otto 板级与运动支持开发，是独立的鸭形构建变体。下述参数属于本仓库固件，尚待真机验收；实拍版本使用自己的配置，区别见[演示与仓库固件](../firmware/README.md#演示与仓库固件)。

## 硬件准备

| 准备内容 | 要点 |
| --- | --- |
| 现成六舵机套件 | 复用 ESP32-S3 主板、6 个舵机、屏幕、麦克风、扬声器、电池和接插件 |
| FlashDuck 打印件 | 按[模型页](https://makerworld.com.cn/zh/models/3146116-shan-mao-zao-wu-flashduckxiao-huang-ya-microduckmi)选择与底座匹配的版本，先试装舵机座、孔位和屏幕开口 |
| 装配配件 | 优先复用螺丝、摇臂和线束；胶水按模型教程准备，备用舵机按故障情况补购 |
| 工具 | 小十字螺丝刀、小斜口钳、USB-C 数据线和架空测试支架 |

已购套件包含摄像头，当前演示未使用视觉感知。到货时清点部件并检查电池、接口和线束。模型来源与许可见[固件说明](../firmware/README.md#来源与许可)，装配步骤参考[FlashDuck 教程](https://shanmaotech.cn/flashduck/)。

## 板卡与接线核对

1. 拆装前记录主板型号、原固件版本、舵机线序和恢复烧录方式；设备绑定信息留在本地。
2. 对照实物、启动日志和板级 [config.h](../firmware/xiaozhi-esp32/main/boards/otto-robot/config.h) 确认引脚。当前固件可自动检测板型，再单独探测摄像头；未安装或未识别摄像头，不能直接判定为无摄像头版主板。
3. 核对鸭形通道：原左手插口连接嘴巴舵机，原右手插口连接脖子舵机，其余四路仍为腿脚。不要沿用人形手臂的动作和校准值。
4. 现有无摄像头版配置的右手通道与屏幕 CS 共用 GPIO12。鸭形固件遇到引脚冲突会禁用动作，状态返回 `disabled`；需要先确认实际线路并完成适配，再接入运动负载。

## 机械装配

1. 保留原有螺丝、摇臂、屏幕排线、电池和接插件，拍照记录拆卸前位置。
2. 按[模型装配教程](https://shanmaotech.cn/flashduck/)调整舵机用途和安装方向，重组腿脚、脖子和嘴巴。
3. 清除打印支撑，先试装舵机座、转轴、孔位及屏幕开口。尺寸不合时先查底座与模型版本，不用胶水强行弥补干涉。
4. 在摇臂未连接机械负载时确认各舵机方向和归位目标，再断电安装摇臂。腿脚、嘴巴和脖子的初始角度不同，不要全部装在 90°。
5. 先完成关节试动和线束整理，再粘接需要固定的部位。胶水避开舵机轴、活动关节和接插件，保留后续拆装空间。

## 固件构建与参数

构建和烧录入口见[固件说明](../firmware/README.md#构建)。先确认板型和引脚，再选择 `otto-duck`；构建成功不代表实物已适配。确认恢复方式与空载试动条件后，再进行烧录。

在 `menuconfig → Otto duck mechanics and display` 设置装配参数。当前默认值如下，均是待校准的起点：

| 参数 | 默认值 | 校准重点 |
| --- | --- | --- |
| 嘴巴闭合／打开 | 45°／60° | 闭合不挤压外壳，打开不顶限位 |
| 脖子最小／中位／最大 | 105°／135°／165° | 核对左右方向、居中位置和线束余量 |
| 步态髋部内收／髋摆幅／脚摆幅／相位 | 25°／44°／34°／108° | 从支撑下的单步试验开始，确认站距和脚部动作 |
| 眼睛窗口 | 左上角 `(72,22)`，大小 `96×96` 像素 | 按实际屏幕开口调整；像素位置不代表打印件尺寸 |

步态起始参数参考 [FlashDuck 步态说明](https://github.com/FlashCat-Jordan/Flashduck/blob/main/firmware/voice/main/boards/flashduck/README.md)。本仓库通过构建配置设置参数，不读取该项目固件保存的调参结果。

修改 `menuconfig` 后使用 `idf.py build` 保留本地配置；再次运行标准变体构建命令会重新生成配置。微调值另存于 `duck_trims`，不沿用原 Otto 变体的 `otto_trims`。

## 逐项校准

1. 架空机器人，在无机械干涉的条件下执行 `home`，检查六路关节的位置和方向。
2. 使用 MCP 工具 `self.otto.set_trim` 调整单个关节，以 1–5° 的步幅修改目标微调值。鸭形头嘴名称为 `mouth`、`neck`，只在空闲时接受校准。
3. 鸭形微调范围为 ±10°。如果仍无法回正，检查舵机齿位、摇臂方向和配置角度，不靠持续加大偏移补偿错误装配。
4. 先分别验证左右转头和单次 `quack`，再在支撑下试一步行走。确认方向和行程后，再逐项测试转向、坐下和跳舞。
5. 单独调整眼睛窗口，检查眼睛、激活码和状态提示在鸭壳开口内是否可读。

鸭形停止、断网停止和超时会取消动作并保持最后输出，不会自动归位。确认结构无阻挡后再发 `home`；保持输出不等于断电，发生堵转或持续异响时应断电检查。

## 联调与验收

先完成 Wi-Fi 配置和灵矽激活绑定，再对照设备实际提供的工具测试语音动作。校准值和动作名称以正在运行的固件为准。

| 顺序 | 测试 | 记录与判定 |
| --- | --- | --- |
| 1 | 架空归位、转头、张合嘴 | 六路方向和行程正确，无机械干涉 |
| 2 | 支撑下单步、转向 | 线束不缠绕，无堵转或供电复位 |
| 3 | 平整地面短距离行走、坐下、跳舞 | 逐项记录稳定性和失败情况，成功前不扩大动作幅度 |
| 4 | 动作刚提交及执行中停止 | 取消后不续跑；需要归位时单独发送 `home` |
| 5 | 动作中断网、恢复连接 | 记录停止延迟，重连后不恢复旧动作 |
| 6 | 语音对话与动作调用 | 检查实际执行、失败反馈和停止响应；动作受理不等于实物完成 |

验收记录应包含代码版本、板卡配置、校准参数、操作步骤和实拍结果。构建与主机测试、实拍样机、仓库固件的真机验证分别记录，统一状态见[实现状态](../docs/ARCHITECTURE.md#实现状态)。
